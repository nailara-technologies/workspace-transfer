## Summary

Added a new `inst-self-signed` command to the letsencrypt zenka that enables quick generation and installation of self-signed Ed25519 ECDSA certificates for local testing without requiring Let's Encrypt integration.

---

## Problem Addressed

**Scenario**: Developers setting up Protocol-7 locally for testing need HTTPS certificates but:
- Don't want to deal with Let's Encrypt complexity
- Need quick certificate generation for local testing
- Want modern Ed25519 ECDSA encryption (consistent with cipher suite modernization)
- May not have internet access for Let's Encrypt validation

**Solution**: Self-contained command that generates and installs certificates locally in seconds.

---

## Implementation Details

### Command Module
**File**: `modules/letsencrypt.cmd.inst-self-signed`
**Size**: 154 lines
**Type**: User-facing CLI command

### What It Does

1. **Checks for Existing Certificates**
   - Looks for `/etc/protocol-7/certs/current.pem` and `/etc/protocol-7/certs/current.key`
   - Returns success if already installed (idempotent)

2. **Creates Certificate Directory**
   - Creates `/etc/protocol-7/certs` if it doesn't exist
   - Uses secure permissions (0700)

3. **Generates Private Key**
   - Uses OpenSSL: `openssl genpkey -algorithm Ed25519`
   - Ed25519 provides 256-bit security equivalent
   - Extremely fast (sub-millisecond generation)

4. **Generates Self-Signed Certificate**
   - Uses OpenSSL: `openssl req -new -x509 -key <key> -out <cert> -days 365 -subj '/CN=localhost'`
   - Valid for 365 days
   - CN (Common Name) set to `localhost`
   - No intermediate CA required

5. **Installs Certificates**
   - Copies certificate to `/etc/protocol-7/certs/current.pem`
   - Copies key to `/etc/protocol-7/certs/current.key`
   - Sets secure permissions (0600) on both files
   - Prevents unauthorized access to private key

6. **Reports Installation**
   - Displays installation summary
   - Shows certificate details
   - Provides usage instructions
   - Lists next steps

### OpenSSL Commands Used

```bash
# Generate Ed25519 private key
openssl genpkey -algorithm Ed25519 -out current.key

# Generate self-signed certificate
openssl req -new -x509 \
  -key current.key \
  -out current.pem \
  -days 365 \
  -subj '/CN=localhost'
```

### Basic Usage
```bash

```

```
✓ Self-signed certificate successfully generated and installed
```

This command aligns perfectly with the cryptography modernization work completed earlier in this session:

**Cipher Suite** (from letsencrypt.cmd.show-cipher-suites):
- Primary: `ECDHE-ECDSA-CHACHA20-POLY1305`

- Fallback 2: `ECDHE-ECDSA-AES128-GCM-SHA256`

**Certificate Authentication**:
- Algorithm: Ed25519 ECDSA
- Key Exchange: X25519 (Curve25519)
- No RSA dependencies

The self-signed certificates generated by `inst-self-signed` use the same Ed25519 ECDSA algorithm as the production cipher suites, ensuring consistent security posture in testing environments.

## Features & Design

### Idempotency ✅
- Multiple runs are safe (returns success if already installed)
- No overwriting or unexpected side effects

### Security ✅
- Private key permissions: `0600` (owner read/write only)
- Certificate permissions: `0600` (can be read for inspection)
- No secrets in logs (no keys printed to output)
- Modern cryptography (Ed25519, not RSA)

### Simplicity ✅
- Single command to generate and install
- No configuration files needed
- No Let's Encrypt account setup
- Works offline

### Compatibility ✅
- Works with existing httpsd configuration
- Uses standard certificate paths (`/etc/protocol-7/certs/current.pem`, `current.key`)
- Compatible with protocol-7's TLS 1.3/1.2 setup
- Integrates with cipher suite configuration

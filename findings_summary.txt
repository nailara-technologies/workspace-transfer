DIFFERENCE BETWEEN HTTP AND HTTPS HANDLER INVOCATION
================================================================================

TCP/HTTP (WORKS ✅):
  1. Client connects to port 80
  2. io.ip.tcp.input.connect accepts → IO::Socket::IP
  3. Session created with protocol='http'
  4. Handler set to: httpd.request_handler
  5. Event loop sees FD as readable (standard TCP)
  6. base.handler.read() called → base.s_read() → IO::AIO::aio_read()
  7. Buffer updated → base.handler.input() → httpd.request_handler
  8. HTTP response sent

SSL/HTTPS (DELAYED UNTIL DISCONNECT ❌):
  1. Client connects to port 443
  2. io.ip.ssl.input.connect accepts → IO::Socket::SSL
  3. Session created with protocol='https'
  4. Handler set to: httpsd.request_handler
  5. Event loop should see FD as readable but... ⚠️
  6. base.handler.read() may not be called during normal processing
  7. Buffer stays empty → base.handler.input() not triggered
  8. Handler eventually called during session cleanup after disconnect


================================================================================
ROOT CAUSE: EVENT LOOP TIMING ISSUE WITH SSL
================================================================================

The problem is NOT with handler registration or the handler chain itself.
Both are properly configured.

The problem appears to be:
  - Event loop doesn't recognize SSL socket FD as readable during normal
    request processing
  - OR base.handler.read() isn't being called by the Event->io() watcher
  - OR there's a synchronization issue between FD readable events and
    buffer watcher activation

This explains why handlers execute AFTER disconnect:
  - Session cleanup triggers
  - Which forcefully calls remaining handlers
  - And handlers execute, but client is already gone
